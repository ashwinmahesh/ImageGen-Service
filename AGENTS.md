# Working on ImageGen-Service

This file is for agents changing the repository. An agent operating the service should read `skill/image-model-server/SKILL.md`. Keep `README.md` written for people: explain what the project does and the implemented techniques behind its image workflow; put a short first-use walkthrough in `QUICKSTART.md` and the full human usage guide in `MANUAL.md`. Detailed contracts belong in `docs/api.md` and `docs/setup.md`.

## Project layout

- `server.py`: generator FastAPI app, validation, media, gallery and direct SQLite queue endpoints.
- `queue_api.py` / `queue_launch.py`: independent queue API and background-process launcher.
- `job_logs.py`: nonfatal per-attempt child capture, scheduler diagnostics and bounded attributed log reads.
- `job_progress.py`: generator-only tracker that turns the running job's stage and runtime step counter into the saved `progress` percentage.
- `resource_probe.py` / `observability.py` / `observability_api.py`: bounded resource probes, independent metric storage/sampler and read-only history routes.
- `job_queue.py`: shared SQLite `JobStore`, ordering, mutations and durable checkpoints.
- `generation_worker.py` / `queue_storage.py`: exclusive consumer, recovery, accelerator coordination and project-local shared queue storage. `model_process.py` / `model_child.py` / `runtime_protocol.py` own backend lifetime and private FD-carrying IPC.
- `model_profiles.py` / `model_assets.py` / `config.py` / `launch.py`: backend defaults, pinned snapshot preflight and startup.
- `photo_workflows.py`: common generate/edit task semantics and preservation scope; masked geometry/compositing lives in `reference_geometry.py`.
- `mflux_engine.py`: offline, per-image low-RAM CLI children for FLUX.2 Klein and Qwen-Image 2.1 Turbo; `engine.py` retains the resident Z-Image path.
- `bootstrap_python.sh` / `bootstrap_uv.sh` / `python_runtime.py` / `runtime_setup.py`: dependency-free setup, compatible interpreter reuse and project-local provisioning.
- `storage_paths.py`, setup/download scripts: portable storage selection and reproducible assets.
- `adapter_catalog.py` / `lora_catalog.py`: queue discovery and generator adapter validation.
- `lora_setup.py` / `adapter_validation.py`: source-preserving custom LoRA downloads/imports, atomic local registration and data-only header/family checks.
- `prompt_expander.py` / `prompt_policy.py` / `enhancer_profile.py`: local prompt expansion; consult `docs/prompt-expansion.md` before changing policy.
- `ui/index.html` / `ui/gallery.html` / `image_catalog.py`: browser UI and catalog.
- `ui_shell.py` / `ui/partials/` / `ui/assets/shell.css` / `ui/assets/shell.js`: one rendered header and queue modal/controller for Generator, Gallery and Observability.
- `tests/test_*.py`: fake-backend, storage, API, queue and recovery tests.
- `tests/smoke_test.py`: explicit real HTTP generation check, run by `make smoke` rather than unit-test discovery.

## Architecture to preserve

There are two services: queue API on loopback port **55302**, generator/UI on **5742**. They share one shared SQLite database. The browser calls generator APIs whose handlers access `JobStore` directly. Do not proxy those operations through the standalone queue API. Its outage is informational for the generator: submission, polling, queue controls, results and generation continue. Use a bounded health probe. Local SQLite failures are different (`503`, `code:queue_storage_unavailable`, `Retry-After:2`).

The queue service owns no GPU, model loading, UI or running-job recovery. It accepts `{model,request}`; omitted model resolves the saved shared default (fresh ready Z-Image, or first ready fallback). Discovery and admission expose/accept only models passing the shared actual asset/runtime preflight. Missing weights never trigger serve-time downloads. Deferred generation/media validation still belongs to the consumer. Preserve readable history/CRUD if the SSD disappears.

`make serve` selects a default, then one global consumer processes all ready model jobs. The generator body stays flat. Freeze each job's resolved model at admission; validation, step/output defaults, reference/edit/mask controls, adapters and LLM guidance follow that model. Global positions/pause/Run Now span models; optional list/clear model filters never select another database. ID routes need no model query. Keep one global worker lease and the independent accelerator lock. Skip unavailable-model/disabled-capability jobs with a visible blocked reason rather than losing them or blocking other eligible work.

SQLite state lives at `<project>/state/queue/jobs.sqlite3`, independent of DATA_DIR. This change intentionally starts a fresh shared queue: the user confirmed no old queued jobs and requested no backwards compatibility or migration. Do not delete existing media/catalogs or add old API aliases. Only the leased generator recovers running jobs. Execute in one reusable managed backend child, exiting/reaping the old process group before a different model starts. Pass per-job GPU/queue descriptors over private IPC and close every received copy after work, retaining a separate worker-lease duplicate for the warm runtime lifetime; descendants must retain locks until exit. HTTP stays responsive, failures affect the job while later work continues, and shutdown finishes the active batch then stops the owned child. Z-Image stays warm for consecutive requests; native CLI backends retain per-image loading.

A batch contains 1–5 sequential images. Persist effective defaults, adapter snapshots, seeds and all planned expansions before rendering. Recovery reuses them and completed artifacts, rendering only missing options. HTTP 202 is acceptance, not completion; partial checkpoints are not full success. Preserve idempotent resubmission. Immediate priority means the next free slot without interrupting an active batch. Pause affects ordinary work only. Persist explicit one-based waiting positions independently of immutable admission sequence. Both APIs support POST job move and run-now through the same atomic JobStore methods. Manual moves override priority order; Run Now puts the same queued identity first and enables immediate scheduling without changing request/fingerprint/checkpoints. Never move or preempt running work. Schema 4 migrates earlier priority order without recovering active jobs on queue startup. Keep the generator header shared across all three pages: identical branding, spacing, navigation, Queue button/badge and runtime status, with only the active navigation link changing. Render trusted local partials through ui_shell.py and keep shared styles/controller in shell.css/js; do not copy page-specific headers. Use unboxed text navigation matching Voice Studio, gray inactive links, a teal current page, underline-only hover feedback and visible keyboard focus. Keep header/page/title dimensions in shell.css: a shared 1400px frame; desktop header 25px × 36px, 30px title and 8px subtitle gap. A shared --page-gap sets equal header-to-intro and intro-to-content distances: 28px desktop, 24px at 1000px and 22px at 720px. On Generator, the tab strip occupies that lower gap, with no extra intro/tab margins, and touches the form/preview top edge; preserve the compact first Model field and visible tab focus. Main horizontal gutters remain 36/22/16px. Follow Voice Studio at 1000px/720px breakpoints, with a 390px generation form (330px at the middle breakpoint, one column on mobile). Apply studio-main/studio-footer on every page rather than restoring different page-local widths/title rules. Keep shared palette tokens in shell.css: Voice Studio background #151617, panel #1d1e21 and input #17181b, with the exact #13b2ba brand icon, lighter readable teal accents and a 140-degree output gradient ending at 65%. Avoid copied per-page palette roots. Keep queue semantic action colors distinct. Generate/Edit are underlined ARIA tabs sharing the workflow panel; update aria-selected, roving tabindex and panel labelling, support arrow/Home/End keys, skip unavailable editors and preserve their setup tooltip and independent drafts. Do not add a first-field margin above Model on top of the form padding. Keep native anchor hrefs and browser-owned navigation so Command/Ctrl-click, middle-click and link context menus work; do not intercept modified clicks or force every click into a new tab. Shared queue callbacks retain generator-owned workflow state; Monitor/Open image/Run Now on other pages open the selected job in Generator without resubmitting. Monitor and Open image load that job's saved request into its own workflow for review (prompt, model/settings, source photo and reused saved mask with its tint) and clear the previous result; uploaded references/masks and gallery images preview through their existing routes, other saved paths show no preview. The header Queue button opens a native dialog with a live active/waiting badge, scrollable entries, fixed header/pagination and modal-local errors. Preserve Close/Escape/backdrop dismissal, focus restoration and keyboard access. Match VoiceGen’s compact blue Monitor, green Run Now and red Remove actions; Monitor closes the dialog and follows without rescheduling. Keep Open image, Retry and Metrics for relevant states. Drag auto-scroll targets the dialog list; closing clears pointer-drag state but keeps polling/monitoring. The UI uses left-hand drag grips plus keyboard arrows, and labels the modal Queue. Delete/clear cancel waiting entries while preserving history/media.

Gallery deletion is separate: DELETE `/v1/images/{id}` removes only that saved PNG, sidecar, editable index and cached previews. Require a UI confirmation showing the selected image, Cancel/Escape without mutation and explicit API deletion by image ID. Block queued/running reference or mask users and unfinished generating batches under the shared SQLite write transaction. Reject ambiguous IDs and nonregular companion/leaf files, preserving external symlink targets. Stage exact owned files in their original folders before erasure, restore on staging failure, report any final cleanup_pending paths and retain uploaded references, other images and job/metrics history. Serialize index/thumbnail publication against deletion; do not resurrect deleted data. Keep UI errors visible and filters/pagination usable after success. Test only synthetic fixtures, including custom paths, cancellation, conflicts, I/O failures and concurrent cache/tag activity. Request replacement is allowed only before the first attempt.

## Observability

Generator-only sampling starts before model loading and stops after its worker finishes. Record model/session/stage and job ID/attempt; poll 1s during execution, 5s idle, plus boundaries, and wake idle sampling on job start. Use a separate project-local `state/observability/metrics.sqlite3` (WAL), never the queue DB or DATA_DIR. Retain raw samples eight days and finished/interrupted attempt summaries. Reconcile old running observations only after acquiring the shared queue’s exclusive worker lease. Sampler/source/storage failures must not block generation, queue CRUD or readiness. Lifecycle events are separate from sampled curves: project-local metric schema 2 adds a durable events table, with no raw-sample retention pruning or retroactive backfill. Use monotonic boundary timers, model/session/action/scope/reason and nullable incoming job/attempt attribution; preserve running/failed/interrupted outcomes and unknown duration. Process start ends at the child’s ready IPC boundary; process stop ends only after the owned group is proven exited, retaining the fatal release guard. Weight scope covers resident Z-Image constructor/adapter reload and release; never label the CLI wrapper as measured native weight loading or include prompt expansion in startup time. Warm reuse adds no event. Negotiate lifecycle events through the execute message so updated children remain usable by an already running pre-upgrade parent. Capture child boundaries over private IPC without giving children their own telemetry DB; storage/observer errors stay nonfatal. Reconcile old events only under the global consumer lease; child interruption has no fabricated duration. Lifecycle history gets independent 24h/7d/30d/90d/all ranges, model/action/scope/job filters, bounded pagination and all-matching successful-operation aggregates. Job views include previous-model release; do not conflate graph windows, scopes or total process/weight time. Keep API errors distinct (`observability_unavailable`).

CPU/RSS includes the generator and children, excluding queue_api.py; normalize CPU to whole-machine capacity. GPU utilization/driver memory is whole-device IORegistry data and may be unavailable. Unified RAM overlaps with GPU memory; RSS can count shared pages twice. Never present null as zero, sampled peaks as guaranteed instantaneous peaks, or job correlation as exclusive GPU attribution. Bound subprocess timeouts and query/downsampling size. Preserve gaps/model/session identity. The UI offers the seven overview windows, model filtering, paginated measured attempts and full/short job windows, with local assets and accessible switches/help. Keep telemetry, test fixtures and histories out of Git. Use fake counters/history for browser tests; distinguish a real counter check from real inference.

## Setup and startup

Python setup reuses the compatible target VENV first, then installed interpreters, and obtains a missing interpreter only during setup under `.python` with a checksum-pinned official uv helper/cache under `.bootstrap`. The full 67-package ImageGen lock supports standard arm64 macOS CPython 3.12–3.14 except 3.14.1 (NetworkX exclusion); validate the complete lock and binary wheels before adding a minor. Preserve broken/incompatible/nonvirtual environments and honor explicit BOOTSTRAP_PYTHON/VENV without silent fallback. Never install into system Python, publish executables to PATH or edit shell profiles. Serving, storage configuration and asset-only downloads use the existing environment directly, without bootstrap/provisioning. Keep model menus, native Chroma requirements, SSD data and project-local SQLite unchanged.

`make setup` lists all supported models (Enter: Z-Image Turbo), marking ready model assets with `[SETUP COMPLETE]` using the shared read-only asset preflight. Keep every model selectable with unchanged numbering/default; do not trust completion markers alone or scan readiness for explicit/noninteractive setup. Then ask for storage (Enter: project-local). External choices create reusable per-model symlinks. Never silently download to a fallback when a configured volume is missing, overwrite conflicting data or recreate retired per-model source projects. Chroma Flash shares the HD encoder/VAE without downloading HD's diffusion checkpoint.

Setup offers `q` at the model menu and handles Ctrl+C throughout its workflow (plus menu EOF) without Python tracebacks. Keep setup work in an owned process group, stop/reap it on cancellation with bounded termination, and never signal unrelated services. Preserve existing files and partial downloads for retries. The initial log must explain reruns: unchanged model weights need no redownload; missing/changed pinned assets update in place while dependencies/shared assets are still checked. Do not promise the entire setup command is a strict no-op or follow unpinned latest revisions.

`make serve` chooses a saved default from ready models while serving all ready models; list unready models separately with setup commands. Label editing-capable model names `(edits enabled)` and mask-capable models `(edit selected area enabled)`, using registry capabilities in both sections. Serving never downloads assets. Require the setup environment and at least one setup model passing readiness before any LLM prompt, queue startup, SQLite creation or service mutation, including explicit MODEL and optional-feature opt-outs; otherwise fail nonzero with make setup guidance. Validate the model/mode before replacing an idle managed server; never replace a busy or unrelated listener. Start/reuse the detached queue API, then run the generator in the foreground. Ctrl-C finishes active work; the queue service stays up. `make stop-queue` stops only the verified queue process.

LLM capability defaults on, with an interactive `[Y/n]` choice. `NO_LLM=1` is the single startup opt-out (`--no-llm` in Python); don't add duplicate flags. API requests default `expand_prompt:false`; the enabled UI checks it by default. Preserve original text/style/constraints, validate expansion budgets and persist provenance. The text-only LLM subprocess exits before rendering. `vary_prompt:true` requires expansion and at least two images. Unique seeds don't guarantee visible diversity.

FLUX.2 Klein 4B uses the pinned Q8 snapshot; Klein 9B and Qwen-Image 2.1 Turbo use pinned Q4 snapshots. Require every indexed shard and Qwen's vision encoder/processor/Turbo schedule before marking setup complete or listing them as ready. Keep child offline/local-model flags and inherited queue/GPU lock descriptors. Both generation and instruction editing are supported; references use the editing pipeline. Keep `task:generate` backward compatible and available for every model. Explicit `task:edit` and `/v1/images/edits` require a source and eligible model, use the dedicated editing-refinement policy, and reject composition variation. Qwen alone accepts aligned masks; pass a 16px-patch max-pooled copy (soft values kept) to inference and composite unselected source pixels back at output resolution with the exact prepared mask. Masked Qwen edits automatically append up to eight `bbox_2d` location boxes built from that prepared (padded) mask, with no setting; keep one 4000-character limit for the complete edit prompt (instruction, preservation, scope and hints) in `photo_workflows.py`, reserve worst-case hint room in refinement, run the authoritative check after box construction and before inference, never truncate or omit parts to fit, and never read media during queue admission. Preserve task/mask/preservation/refinement through queue recovery and gallery reuse. The UI filters setup models by task; switching follows queued jobs rather than restarting the API. Reject `image_strength` on these instruction editors and hide the variation control in the UI. Keep new quantization/license metadata under the exact model-ID namespace and preserve it when recording expansion provenance.

Only Realism is an optional public adapter preset. Default setup downloads no LoRAs. Keep private catalogs, weights and preset names out of tracked files and download defaults. `make setup-lora` adds supported Z/Chroma adapters to ignored per-model `loras/custom.json`, merged separately from shipped/legacy catalogs. Reserve `custom-` IDs for user entries. Keep sources/cache files unchanged, pin Hub downloads to full commits, checksum staged safetensors copies and publish catalog changes atomically under the install lock. Preserve same-ID no-op/repair and reject conflicting replacements. Public download paths must use `local=False` and never ingest private additions. Discovery reads fresh local metadata without importing inference runtimes; installing an adapter does not start services or set up its base. Preserve project-local/external-storage Git-pull and cancellation/concurrent-install tests. The loader inserts configured triggers; don't require `<lora:...>` prompt tags.

Prefer toggle switches over checkboxes for on/off settings: use an accessible switch (`<input type="checkbox" role="switch">` styled as a toggle) for every boolean UI setting rather than a plain checkbox, labeled **Prompt expansion** for the local LLM control. Keep all help icons as grey circled question marks, and inset select chevrons from the right border. Preserve native input checked/disabled semantics and keyboard control. Queue controls match VoiceGen: local 14px outline SVGs with `aria-hidden`, visible text labels, opaque muted blue/green/red action fills, and 32px row controls with a 92px minimum desktop width. Use neutral solid fills for other queue controls, preserve hover/focus/disabled states, and let controls wrap on narrow screens. Decorative icons must not alter accessible names or intercept button actions. The shared header's **Process queue** accessible switch (on = processing) and the matching switch in the Queue modal header (before Clear waiting and Close, which stay right-aligned) both send `PATCH /v1/queue` and mirror the polled `/health` `queue.paused`. Polls must not move the switch while a change is in flight; restore the saved state and announce a failed change.

Enable the Edit photo tab whenever discovery contains at least one setup editing model, regardless of the current generation model. The first visit to Edit leaves the model selector empty with a disabled “Choose an editing model…” placeholder; later visits restore its own selection. Generation/expansion stays disabled until a setup editing model is selected. Never fall back to the generation default while editing. With no editing-capable setup model, disable the tab; preserve the hover/focus tooltip and its model-name setup guidance. Refresh availability after discovery/model changes and submission cleanup.

Selected-area API edits must work through both the generator's flat request and the standalone queue's `request` envelope. Keep queue admission independent of source/mask reads and defer model/media validation to consumption. Document complete examples in both schemas/references and verify masks survive preparation, checkpoints and recovery without re-rendering committed artifacts.

## Verification and data boundaries

Keep cross-test imports under `tests` and resolve source/assets relative to the project root, one directory above the test files. Run focused tests while iterating and relevant complete checks for behavior changes. Documentation-only edits need link/example/schema review rather than GPU generation. `make smoke` requires a running generator and creates a real image; report it separately from unit tests.

Use benign browser fixtures and label simulated screenshots/timings. Do not change user queues, use private media, start a second GPU model or restart busy services just to test. Preserve unrelated and pre-existing user-started processes. After maintenance, stop generator/queue instances you started unless asked to leave them running; this user starts ImageGen manually.

Git contains source, docs and the four approved screenshots under `docs/screenshots/`. Keep weights, runtime binaries, LoRAs, references, outputs, sidecars, indexes/tags, SQLite state, settings, symlinks, environments, caches, logs and credentials ignored. Inspect staged paths before committing. Preserve actual data on cleanup; a source-only clone starts with an empty queue.
