# Local image model service

Locate the checkout containing `Makefile`, `model_profiles.py`, `server.py` and this README. On the original Mac it is `~/Documents/models/ImageGen-Service`; elsewhere use the supplied folder. The separate local per-model source projects have been retired; do not recreate them or use their environments. The shared project owns its environment/runtime, while same-named SSD model/data directories remain required. Read `README.md` before provisioning or changing settings; live `/openapi.json` is authoritative for request/response fields. This skill is usable directly by any AI tool without installation.

Run `make setup` in a terminal to choose a model from the menu; Enter selects **Z-Image Turbo**. It then asks once for a model store directory; Enter uses the project folder, another absolute path creates per-model symlinks. For scripts use `make setup MODEL=<id> DATA_DIR=/absolute/store NONINTERACTIVE=1`, or omit DATA_DIR to reuse saved/default storage. Valid IDs: `z-image-turbo`, `chroma1-hd`, `chroma1-flash`. The store contains these three model subfolders plus a shared prompt-enhancer folder. Do not pass one model's weights folder as the store. Keep source/environment internal and weights/data on the user's chosen external volume. Reuse existing assets; fail on missing mounts rather than downloading a fallback. Flash setup fetches shared T5/VAE assets without downloading the HD diffusion checkpoint. Realism for Z-Image is the only optional public adapter; never publish personal catalogs/media.

Run `make test` for fake-backend checks. Start `make serve MODEL=<id>` in a retained foreground terminal, optionally `NO_LORAS=1` or `PORT=...`. Plain `make serve` assigns numbers only to models with a completion marker and required local assets (including shared dependencies/runtime). Unready models are listed separately without numbers, each with a make setup MODEL=<id> command; they cannot be selected until set up. Enter and omitted noninteractive serving selection prefer ready Z-Image, otherwise the first ready model. With none ready, show setup guidance and exit without touching existing services. Setup still lists every supported model and defaults to Z-Image; missing volumes fail clearly. Discovery does not load GPU weights or checksum all assets, and an explicit MODEL still validates before switching services. The default UI is `http://127.0.0.1:5732/` (or localhost:5732), with `/docs` and `/gallery` on the same origin. Use any explicit PORT override consistently for serve/health/smoke; no hosts-file mapping is installed. An identical managed model/mode is reused, so the new launch command can exit while the original terminal owns it. Poll `/health` until ready (the listener may be absent during initial loading); confirm `model`, `busy`, `loras_enabled`, paths and `capabilities`. `/v1/models` lists supported/downloaded models. Only one selected backend serves requests. A different request model returns 422; select it at startup instead. Do not replace a busy/unrelated service. Graceful Ctrl-C stops the foreground process.

Use live `/openapi.json` or `/docs` for authoritative fields/defaults. POST `/v1/images/generations` with a prompt and `response_format:"url"`; omit model/steps to use active defaults. Defaults: Z-Image 9 steps (max12), HD40 (max80), Flash8 (max40). `size` dimensions are multiples64, 256–2048. Seed is optional uint32, n is a strict integer1–5 (default1), prompt max4000characters; Z-Image truncates at512tokens including formatting. Optional `output_dir` is server-local absolute/`~/` path. Only completed generation results return PNG and metadata paths; asynchronous acceptance returns a job ID first. The API rejects unlisted fields, including negative prompt/CFG/sampler/mask options; no model-specific option namespace exists yet. Optional tags are saved and editable later.

Prompt expansion is optional: setup downloads a shared Qwen3.5-2B 4-bit LLM, but plain serving leaves it disabled. `make serve WITH_LLM=1` enables it; confirm `/health.prompt_expansion.enabled`. Send strict `expand_prompt:true` on generation/jobs to expand (API defaultfalse; UI initiallychecked in enabled mode). The image-specific system prompt returns structured style_details plus optional additional_composition and requests evocative concrete visual detail and develops the requested medium/style/aesthetic, while preserving stated subjects/counts/actions/colors/composition/exclusions. Original text is retained verbatim with added detail. Guidance is selected by image backend; inspect /health.capabilities[model-id].prompt_expansion_guidance and saved image_model/guidance_profile/guidance_version/policy provenance. Chroma Flash currently inherits HD content guidance; do not infer a shorter prompt requirement from fewer steps. See docs/prompt-expansion.md for evidence and limits. It sees no reference image. POST `/v1/prompts/expand` with `{prompt}` and optional adapter fields previews without creating an image job; busy accelerator returns409, disabled mode422. Review `expanded_prompt`; accepting it manually as a new prompt should use expand_prompt:false. Saved gallery settings already use expanded text without re-expanding. Z expansions are checked against512 exact image-tokenizer tokens including chat formatting/trigger; over-budget text fails, never compresses/truncates. Chroma native token counts are unavailable (null); API4000character cap still applies. Durable automatic expansions are persisted before rendering and reused after restart. With LLM mode off, waiting jobs requiring it remain queued. Inspect `job.prompt_expansion` or completed `result.data[0].prompt_expansion`, also saved in sidecars with original `prompt`, `expanded_prompt` and actual `effective_prompt`. Rendering time excludes additional prompt_expansion.seconds. `make download-llm` resumes the pinned shared download; setup installs its pinned runtime too.

For multiple options send common `n:2` through `n:5` (UI default1). One durable batch renders sequentially from the same original prompt; expansion is shared unless vary_prompt:true requests distinct composition prompts; seeds increment from the admitted first seed modulo2^32. Iterate every item in completed `data[]` or job `result.data[]`; never assume only data[0]. Items include candidate_index/count, seed and paths. Job completed_images/total_images report progress; partial_result contains only saved options while running/failed, not a successful full batch. Recovery adopts completed candidate files and renders missing options with stable IDs/seeds; LLM expansion is reused. A failed batch preserves completed images; explicit retry creates a new full batch. Active batches finish before later priority work. In the UI, choose a thumbnail to preview/download/reuse that candidate; queue-history View reopens the batch.

For variations, pass an absolute `reference_image`, or POST raw image bytes to `/v1/reference-images` (20MiB/40MP max) and use its returned path. Output preserves oriented reference aspect ratio; only the larger dimension in size sets the long edge. Saved dimensions need not be multiples64 and the short edge can be below256; temporary model padding is trimmed. `image_strength` is [0,1), higher preserves more; default.6, requires reference and at least2steps. References remain unchanged. This is image-to-image variation, not reliable localized/instruction editing. LoRAs come only from the active model's `/v1/loras`; use ID/strength fields, not prompt tags. A configured trigger phrase is inserted automatically. Strength0–2, one adapter. Base-only mode rejects adapter requests.

The webpage `/` offers generation/reference controls. `/gallery` and GET `/v1/images` combine all model roots, searchable by prompt/tags/model and paginated using limit1–100(default24),offset,sort. Exact repeated tag filters combine with q. Read `/v1/images/{id}` for settings; PATCH `/v1/images/{id}/tags` with `{"tags":[...]}` replaces tags, `[]` clears them. Changes persist in the owning model index without changing original PNG/metadata. Reuse actions prefill for review; cross-model adapters/steps are not transferred. Custom output URLs survive restart through the index; preserve indexes and data paths.

Prefer POST `/v1/jobs` to persist a request and receive202 plus an ID, then poll GET `/v1/jobs/{id}`. Each model's SQLite queue is at `<project>/state/queues/<model-id>/jobs.sqlite3`, automatically resumed at startup. All SQLite databases/journals/backups/worker leases stay project-local and Git-ignored; DATA_DIR controls weights/media, not SQLite. On upgrade, startup migrates an old store-local queue only after taking both worker leases, verifies a SQLite backup, retains it locally and retires the old DB/sidecars. Stop the legacy worker first; conflicts fail without overwriting either queue. API jobs default `generate_immediately:false` (ordinary FIFO); the UI defaults true (next free slot ahead of ordinary work, FIFO among immediate jobs, no preemption). The synchronous `/v1/images/generations` remains compatible, defaults immediate=true, and waits on the same durable worker. Use a long timeout for that route. Disconnection never cancels a job. Reuse the same `Idempotency-Key` and request after uncertain submission; different settings with that key return409. Seeds and effective defaults are fixed on admission. Poll until succeeded/failed/cancelled; only succeeded includes the complete `result.data[]` with file_path, metadata_path and url (for response_format:url). HTTP202 means persisted acceptance, not a finished image. Failed jobs return HTTP200 with status/error on GET; do not mistake that for generation success. Prefer response_format:url to avoid repeatedly embedding large base64 PNGs.

GET `/v1/jobs?status=pending&limit=24&offset=0` lists active/waiting jobs with totals/navigation (next_offset/previous_offset omitted at page boundaries); omit status for history (limit1–100/offset). DELETE `/v1/jobs/{id}` cancels only waiting entries (running/finished returns409, unknown404); DELETE `/v1/jobs` clears all waiting work for the active model and returns `{"cancelled":count}`. History and generated files remain intact. POST `/v1/jobs/{id}/retry` creates a new normal FIFO job from a failed/cancelled record. PATCH `/v1/queue` with `{"paused":true}` (or false to resume) persists an ordinary-queue pause, allowing the current image to finish and explicitly immediate work to run. Base-only mode leaves an incompatible adapter job waiting rather than silently changing it.

Graceful shutdown finishes current inference and persists the remainder; an abrupt interruption retries the same job ID/seed from scratch. Committed matching artifacts are reconciled without duplicate generation. Preserve queued references/adapters and back up the database/index/media together. Missing SSDs fail without fallback. GPU_LOCK_FILE or ignored storage.json gpu_lock_file selects a cooperative accelerator lock; this Mac uses the voice services' existing SSD lock. Pending jobs wait for it; it does not unload idle resident models. Inspect `/health.queue` for counts, pause/stage/error. Do not clear user queues or interrupt active work for validation. This user starts the image service manually: after maintenance/testing, stop any image server you started and leave it stopped unless explicitly asked to keep it running. Verify ownership and let active generation finish; preserve unrelated or pre-existing user-started services. For actual GPU verification, `make smoke` generates/decodes a512px image using the active defaults. Distinguish this from unit tests. Chroma loads/reclaims GPU weights per request and can be slow. Do not start additional GPU models merely to read catalog or docs. Report the selected model, mode, URL, paths and actual checks; retain media, weights, local settings, catalogs and storage symlinks outside Git.

For noticeable batch variety, serve WITH_LLM=1 and send n:2–5, expand_prompt:true, vary_prompt:true (strict boolean; API default false). The UI checks “Different compositions with LLM” by default when count>1 and expansion is enabled. Distinct composition briefs fill only unspecified framing/layout/depth/light while keeping the original description verbatim and preserving subjects/style/explicit constraints. All candidate_expansions[] are saved before rendering and reused after restart; result.data[i].prompt_expansion is that image’s actual applied expansion. Inspect/reuse the chosen candidate’s prompt. Shared/single expansion remains available with vary_prompt:false; seed-only alternatives remain supported with expansion off. Turbo can converge on similar layouts; a unique seed/file or different wording does not establish perceptual diversity. Strong references/tight framing can limit variety; lowering reference preservation allows greater deviation. The single-expansion preview is disabled while varied compositions are selected.
