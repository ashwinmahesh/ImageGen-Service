# Operate ImageGen-Service

Use this skill to set up or call the service. For repository edits, follow `AGENTS.md` in the checkout. The human-facing `README.md` provides the quick start; `docs/setup.md` covers advanced configuration; `docs/api.md` covers request fields, results, queue semantics and recovery. Read the reference relevant to the task. Each live `/openapi.json` is authoritative for its service. No Codex plugin, shell alias or chat history is required.

Locate the provided checkout containing `Makefile`, `server.py` and `model_profiles.py`. On the original Mac it is `~/Documents/models/ImageGen-Service`, with model/media storage at `/Volumes/ASH-SSD/models`. Elsewhere use the supplied checkout and chosen store. ## Setup and startup

The interactive setup list marks models whose required local assets are ready with `[SETUP COMPLETE]`. It checks the same local files as the serving menu, including shared assets/runtime and indexed shards; labels do not load weights or indicate optional LLM/LoRA readiness. All models remain selectable, including completed ones. Explicit model and noninteractive setup skip this scan and menu.

Choose `q` at the setup model menu or use Ctrl+C at any setup stage to cancel cleanly (menu EOF also cancels). Setup stops only its own subprocesses and keeps existing/cached partial downloads; rerun it to finish or repair interrupted setup. Reruns reuse unchanged model weights without redownload and update missing/changed pinned files in place. Dependencies/shared assets are still checked, so the whole command is not a strict no-op. Do not delete model folders, environments or queues merely because setup was cancelled.

Run `make setup` in a terminal: Enter chooses Z-Image Turbo, then project-local storage on a fresh checkout. Another absolute folder creates reusable per-model symlinks. Automation: `make setup MODEL=<id> DATA_DIR=/absolute/store NONINTERACTIVE=1`; omit DATA_DIR to reuse saved/default storage. IDs: `z-image-turbo`, `chroma1-hd`, `chroma1-flash`, `flux2-klein-4b`, `flux2-klein-9b`, `qwen-image-2.1-turbo`. Klein 4B uses a pinned MLX Q8 checkpoint; Klein 9B and Qwen Turbo use pinned Q4 checkpoints. Setup checks indexed shards and Qwen's vision encoder/processor/Turbo schedule before recording completion. DATA_DIR is the parent store containing model folders, not one weights folder. Reuse existing assets; fail on missing mounts instead of creating fallback data. Setup downloads selected image assets and the shared prompt LLM, no LoRAs. Realism is the only optional public preset.

Setup automatically reuses a compatible target environment, then installed CPython; only setup downloads missing Python into project-local `.python` using a checksum-pinned uv helper under `.bootstrap`. The full lock supports standard native Apple Silicon CPython 3.12–3.14, except 3.14.1. No system Python, global packages, PATH or shell-profile changes are needed. Optional setup overrides: `BOOTSTRAP_PYTHON=/absolute/path/to/python3.12` and `VENV=/absolute/internal/path/.venv-new`; keep VENV consistent on later commands. Broken/incompatible/nonvirtual environments or conflicting explicit interpreters are preserved with an error, never silently replaced. Serving, queue and model-only download commands use the existing environment and never provision Python/packages. Chroma’s native macOS requirement is unchanged; see `docs/setup.md#python-selection`.

Start `make serve MODEL=<id>` in a retained foreground session when requested. Plain `make serve` chooses a default from ready models, reusing a ready saved default then ready Z-Image/first ready fallback. All setup models can process jobs without restarting. Unready setup commands remain visible in the terminal menu. The menu labels Klein `(edits enabled)` and Qwen `(edit selected area enabled)` in both sections. Serving never downloads. Require a setup environment and at least one model passing readiness before any LLM question, queue startup or service mutation; otherwise exit nonzero with `make setup` guidance. Explicit MODEL and optional-feature opt-outs do not bypass setup. LLM capability defaults on; Enter/Y keeps it, N disables it for that run. `NO_LLM=1` is the single startup opt-out. `NO_LORAS=1` disables adapters independently. Missing requested assets fail before replacing an idle server. Never silently change modes or interrupt busy/unrelated services.

The generator/UI is `http://127.0.0.1:5742/`, with `/gallery`, `/docs` and `/health`. Use PORT overrides consistently. Wait for ready and confirm saved default, paths, `loras_enabled` and `prompt_expansion.enabled`. The API starts without loading image weights; models load on demand in a managed child while the listener stays responsive. An identical managed instance may be reused. Ctrl-C finishes the active batch and stops the generator; the queue stays up.

`make queue` starts/reuses a detached API at `http://127.0.0.1:55302`, using the installed environment without model/LLM/SSD/GPU requirements. `make serve` ensures it is up too. `make stop-queue` stops only the verified queue process, preserving jobs. Use QUEUE_PORT overrides consistently. No OS autostart is installed.

## Install a custom LoRA

From the located checkout, use `make setup-lora` interactively or the following noninteractive form after base setup:

```sh
make setup-lora MODEL=z-image-turbo \
  LORA_SOURCE="/absolute/path/style.safetensors" \
  LORA_ID=ink LORA_NAME="Ink illustration" \
  LORA_TRIGGER="creator-trigger" LORA_STRENGTH=0.8 NONINTERACTIVE=1
```

Use the creator's real trigger, or omit it when none is required. This importer supports Z-Image Turbo and Chroma HD/Flash only; do not claim Klein/Qwen adapter support. Choose a LoRA trained for that model, check its license, and distinguish header/family checks from proven runtime compatibility. Use an existing local `.safetensors`, a Hugging Face `owner/repo` plus `LORA_FILENAME`, or a full HTTPS `blob`/`resolve` file URL. `LORA_REVISION` optionally pins repository sources; otherwise branches/tags resolve to a recorded full commit. An optional `LORA_SHA256` rejects unexpected bytes. HF_TOKEN/existing Hub login supplies authorized access; never put tokens in URLs/catalogs. Keep VENV/DATA_DIR overrides consistent; omit DATA_DIR to reuse storage. See `docs/setup.md#custom-lora-downloads-and-imports` for exact options.

The returned ID includes `custom-` (example: `custom-ink`). Discover it with GET `/v1/loras?model=z-image-turbo` and require `available:true`, then submit `lora:"custom-ink"` and optional `lora_strength`. Configured triggers are inserted once; do not add `<lora:...>` tags. One adapter per request, strength0–2. No server restart is normally needed; reload/reselect the UI model. A generator in NO_LORAS mode must be restarted with adapters enabled when requested; installation does not start it or set up base weights. Only setup models appear in discovery/UI.

Weights, Hub cache and `custom.json` remain in ignored model-data `loras` folders, not tracked code. Chroma variants share the HD folder but require explicit compatibility registration for each. Shipped/legacy catalog files remain unchanged and public setup ignores custom entries; `git pull` preserves them. Rerunning identical ID/weights/settings is verified reuse; choose a new ID for changed settings/versions. Cancel with q/EOF/Ctrl+C, retaining prior registrations/cache. Preserve adapters required by queued work and back up user catalogs with their weights. Do not hand-edit the shipped catalog to install a personal adapter.

## Choose the API

| API | Request and default model | Results |
| --- | --- | --- |
| Generator, port 5742 | POST `/v1/jobs` with flat image settings. Omitted model uses the shared saved default; explicit setup models switch automatically between batches. | Completed `result.data[]` has paths and URLs/base64. |
| Queue, port 55302 | POST `/v1/jobs` with `{"model":"z-image-turbo","request":{...image settings...}}`. Omitted model uses the shared saved default. | Raw persisted metadata, local paths; batch `images[]`. No media/UI routes. |

For both, HTTP 202 means committed, not generated. Preserve the ID and poll GET `/v1/jobs/{id}` until `succeeded`, `failed` or `cancelled`. Only succeeded is a complete result; partial checkpoints may exist earlier. Reuse the same `Idempotency-Key` and settings after uncertain submission; changed settings with that key return409. Prefer `response_format:"url"` on the generator to avoid embedding PNGs repeatedly, and iterate every result item.

Example generator body:

```json
{"prompt":"A watercolor fox beneath an oak tree","n":3,"expand_prompt":true,"vary_prompt":true,"response_format":"url"}
```

For the queue API, wrap it in `request`. GET `/v1/jobs` lists all models by default; optional `?model=<id>` filters list/clear only. Positions and pause are global. Detail/update/cancel/retry/move/Run Now address unique job IDs without a model query. GET `/v1/models` lists only setup models; new requests for unready models return422 with setup guidance. GET `/v1/loras?model=<id>` discovers compatible adapters without a generator; select available IDs and optional strength. Presence is not checksum verification or a generator-mode check. A missing configured volume/bad catalog can return503 while queue CRUD remains usable. Both LoRA endpoints accept `?model=<id>` (shared default if omitted); generator discovery also reports its enabled mode.

Queue admission validates routing/JSON/priority; the consumer later validates image settings and freezes defaults/seeds/adapter snapshots before inference. The consumer switches automatically for other setup models. Jobs requiring unavailable model files or disabled optional capabilities remain waiting, with a blocked reason, while eligible jobs continue. Inspect failed job errors; HTTP200 from a status read is not generation success. The synchronous `/v1/images/generations` waits on the same durable worker and needs a long timeout. Disconnecting never cancels persisted work.

## Generation controls

- `n`: integer 1–5, default1. Sequential options share settings; seeds increment from the persisted first seed modulo 2^32. Omit seed for a random first seed. Each result has seed, paths and candidate index/count.
- `expand_prompt:true`: API defaultfalse; enabled UI’s Prompt expansion switch initially on. Text-only LLM appends visual details preserving original text/style/constraints. Preview with POST `/v1/prompts/expand` when useful. Adopting preview text should turn expansion off to avoid a second pass. Generation policy7 automatically retries an unusable structured response once per candidate in the same LLM, preserving constraints. New expansion records report `structured_output_attempts` (1–2) and optional `structured_output_retry_reason`; older/edit records may omit them. Persistent failures report the format category without raw model output and render no image. Preview again or explicitly disable expansion if desired; budget/truncation/fidelity failures remain errors. The180-second child deadline includes repairs.
- `vary_prompt:true`: requires expansion and n>=2, giving each option a saved composition expansion. UI enables it for eligible batches. All expansions persist before rendering; recovery reuses saved options/prompts/seeds and renders only missing images. Constrained prompts/strong references can limit visible variety.
- `size`: omitted without a reference defaults to1024x1024. With a reference, omit or use `"auto"` to detect its oriented dimensions without upscaling, capped at2048px long edge. Explicit dimensions must be multiple64 from256–2048 and override the long edge; auto without a reference is rejected. Default/max steps: Z9/12, HD40/80, Flash8/40, Klein4/4 (both sizes), Qwen Turbo8/8. Start Qwen Turbo around1024px for detail; smaller sizes remain accepted. Prompt max4000characters; Z's backend processes512tokens including formatting/trigger. Expanded Z prompts use exact tokenizer budget checks and fail rather than compress/truncate. Chroma and Klein/Qwen expansion-token counts are unverified; do not substitute the LLM tokenizer.
- `reference_image`: absolute server-local path, or upload raw bytes to POST `/v1/reference-images` (not multipart;20MiB/40MP). Output follows oriented reference aspect ratio. Auto detects source resolution (2048px long-edge cap); explicit size uses its larger dimension as long edge. Trimmed dimensions need not be multiples64. `image_strength` [0,1), default.6, applies only to Z-Image/Chroma variations; higher preserves more. Klein/Qwen perform instruction editing through `prompt` and `reference_image`: omit `image_strength` (explicit values are rejected). All references require at least2steps. One reference only. Qwen photo edits accept `mask_image`; whole-photo edits do not guarantee unchanged pixels. `/health.capabilities.reference_mode` and `image_strength_supported` distinguish these workflows.
- `lora` / `lora_strength`: one available compatible ID, strength0–2. Configured triggers are inserted automatically; don't add `<lora:...>` prompt tags. Base-only mode rejects new adapter requests.
- `output_dir`: absolute server-local folder or `~/...`, otherwise `<store>/<model>/images`. PNG and JSON sidecar are always saved; original references are unchanged. Paths belong to the server, not the caller.

Read `docs/api.md` for remaining fields, errors and provenance. Negative prompt, CFG and custom sampler/scheduler controls are not exposed; Qwen photo edits support an aligned mask. No model-specific request-option namespace exists yet. Klein/Qwen quantization and verified license notices are under their exact model-ID key in capabilities/discovery and saved metadata. Commercial model use of Klein9B and Qwen Turbo requires a separate license from the respective owner; Klein4B is Apache2.0. Notices inform users without adding an acknowledgment step. The new MLX backends load local weights in offline low-RAM children per image and release them on exit; ready status is asset/worker preflight rather than a warm model. Inherited worker/GPU leases stay with the child.

## Generate versus Edit photo

Keep all models, including Klein and Qwen, available for generation without a source photo. The webpage has underlined Generate and Edit photo tabs (teal marks the active tab; arrow/Home/End keys switch available tabs); editing filters choices to Klein4B/9B and Qwen Turbo. Edit photo is available whenever at least one setup model supports edits, regardless of the Generate selection. Its model selector starts empty on the first visit; choose a setup editor before submission or expansion. Later visits restore its own selection. Do not resolve an empty edit choice to the default generation model. If no editing model is setup, the tab is disabled and its hover/focus tooltip retains the supported-model setup guidance. Editing requires a source, defaults to Auto source resolution (2048px long-edge cap) and the model's distilled steps, optional preservation text, and a separate text-only refinement policy. Only setup models appear in the webpage; each request selects its own model, and loading happens automatically when scheduled.

Use flat POST `/v1/images/edits` for a synchronous JSON edit, or POST `/v1/jobs` with `task:"edit"` for asynchronous editing. Pass `reference_image`, edit instruction in `prompt`, optional `preserve` (up to1000characters), and optional `expand_prompt:true`. Refinement clarifies only requested changes and preserves unrequested content; it never uses generation composition/style expansion and cannot see the photo. `n` gives alternate attempts at the same edit; `vary_prompt:true` is rejected. Generation defaults remain compatible and explicit `task:"generate"` is optional. Preview refinement with POST `/v1/prompts/expand` and `task:"edit"` plus optional preserve.

Qwen alone accepts `mask_image`: an absolute local grayscale mask matching the oriented original source dimensions (white edits, black preserves). Upload a mask PNG through `/v1/reference-images` if needed. The UI lets users drag a rectangle on an uploaded/gallery source preview. Masks are scaled/padded with the photo, passed to Qwen, then composited so unselected pixels are copied exactly from the normalized source at output resolution. Empty/misaligned masks fail; Klein masks are rejected. Keep source/mask files accessible for queued jobs and restart recovery. Sidecars save task/preserve/mask/edit_scope/effective prompt, and image responses identify task. Gallery reuse restores edit settings; a saved mask can be reused or cleared.

Selected-area edits work on both APIs: generator port5742 accepts flat `{task:"edit",reference_image,mask_image,prompt,...}` on `/v1/jobs` (or synchronous `/v1/images/edits`); queue port55302 accepts `{model:"qwen-image-2.1-turbo",request:{task:"edit",reference_image,mask_image,prompt,...}}` on `/v1/jobs`. Poll the returned queue job ID without a model query. The queue does not inspect/upload/copy media; missing/invalid masks fail at consumption. Keep referenced files unchanged and accessible until completion/recovery. Both schemas and `docs/api.md` include selection examples.

## Queue and gallery

POST `/v1/jobs` defaults to the queue end; UI defaults `generate_immediately:true` (next free slot, never preemption). New immediate admissions insert before the first ordinary job, after any leading immediate jobs; explicit moves define saved execution order. GET `/v1/jobs?status=pending&limit=24&offset=0` lists active/waiting work; omit status for history, limit1–100. Lists omit image blobs. PATCH a never-started queued job with a **complete replacement request** (flat on generator, `{request:...}` on queue). Attempts>0/nonqueued returns409; model cannot change.

POST `/v1/jobs/{id}/move` with `{"position":N}` moves a waiting job to a one-based position across the entire waiting queue, independent of pagination. Read `queue_position` first; add/subtract 1 to move down/up. Manual moves may cross immediate jobs and preserve request/priority/checkpoints. POST `/v1/jobs/{id}/run-now` (no body) moves that same job first and enables immediate scheduling, even while paused. It never interrupts an active batch, starts an offline generator or enables missing capabilities. The current top-level priority may differ from the unchanged request's original flag. Both operations return200; active/finished jobs or stale out-of-range positions409, unknown ID404, malformed moves422. Recovered waiting attempts can move without changing frozen progress. Job-ID operations on both ports use the ID alone; optional model filters apply only to list/clear. Generator operations stay direct SQL during queue HTTP outages. Generator, Gallery and Observability share the same header, plain text navigation and live status. All use the Voice Studio-sized 1400px frame and shared header/title spacing; generator columns adapt for smaller screens. Teal marks the current page; the other links stay gray. Native links support Command-click on Mac, Ctrl-click on Windows/Linux and middle-click to open another tab; a normal click stays in the current tab. The header Queue button (active/waiting badge) opens the same scrollable native modal on every page with pause/clear, filters, pagination, drag grips, keyboard ↑/↓ and Run Now. Monitor closes it and follows the job without changing scheduling; Monitor/Open image/Run Now from Gallery or Observability open the generator at `/?job=<id>` for its preview (the link itself does not submit work); Open image shows completed results, while Metrics opens resource history. Queue controls pair decorative outline icons with text labels and match VoiceGen's compact sizing and muted solid fills: blue Monitor, green Run Now and red Remove, with neutral secondary actions. Close/Escape/backdrop dismisses it; queue mutations/errors remain in the modal. Closing the modal does not stop polling, jobs or monitoring.

DELETE `/v1/jobs/{id}` cancels waiting only; DELETE `/v1/jobs` cancels all waiting work across models (or an explicit model filter), preserving running work/history/media. POST `/v1/jobs/{id}/retry` creates a new ordinary identity from a failed/cancelled entry. PATCH `/v1/queue` with `{"paused":true}` pauses ordinary work only; immediate jobs can still run. Generator counts/stage/errors appear in `/health.queue`.

GET `/v1/images` on the generator browses all model roots/indexed custom destinations: `q`, repeated exact `tag` filters, `limit`, `offset`, `sort`. Pagination includes totals/navigation; generator null offsets are omitted. GET `/v1/images/{id}` reads settings. PATCH `/v1/images/{id}/tags` with `{"tags":[...]}` replaces labels (`[]` clears); at most32 labels, each1–64 normalized characters, without commas/control characters. Edits do not alter original PNG/sidecar. Gallery reuse fills the form for review rather than submitting. In the gallery image details, **Edit photo** opens `/?generation=<image-id>&mode=edit` with that PNG visible in the Edit preview, a blank edit instruction, no adapter/old mask and Auto resolution. Any setup editor can edit an image from another model. Selection prefers an eligible original model, then an eligible saved default, then the sole available editor; otherwise choose a setup editor. With none, the action is disabled with setup guidance. Describe changes and submit explicitly; the original stays unchanged. Variation and settings reuse remain separate actions.

DELETE `/v1/images/{id}` on the generator permanently removes the PNG, adjacent JSON settings, editable-tag index and cached previews; no body or model query. Use the gallery image ID, not its batch job ID, and only delete images the user has authorized removing. The UI exposes **Delete image** in details and requires confirmation with a preview; Cancel/Escape sends no deletion. The API call itself authorizes deletion. Success is 200 `{id,deleted:true,cleanup_pending:[]}`; 404 means missing/already removed, 409 means in-use/unfinished batch or ambiguous/nonregular files, and 503 indicates storage failure (SQLite has queue_storage_unavailable). Finish/cancel referenced jobs first. Uploaded references, other images and job/metric history remain; old result URLs may return404. There is no undo. A nonempty cleanup_pending reports renamed private files that still need explicit disk cleanup; check the log/permissions rather than claiming all bytes were erased. After an uncertain response, GET detail/refresh before retrying. Deletion uses direct project SQLite and works during a standalone queue HTTP outage; do not start inference just to delete. Preserve current gallery filters/pagination, returning to the last available page if deletion empties it.

## State, outages and checks

SQLite is project-local at `state/queue/jobs.sqlite3`, with journals/backups/leases alongside; DATA_DIR never relocates it. Both services use the same JobStore directly. The browser calls only generator APIs and keeps working if standalone queue HTTP stops. `/health.queue_api` reports available/url/recovery_command/error through a bounded one-second probe; the notice is informational and controls stay usable. Restore outside-agent access with `make queue`, no generator restart. Local SQLite failures instead return503/code=`queue_storage_unavailable`/Retry-After2; retain an unconfirmed submission's idempotency key.

Only the leased generator recovers interrupted jobs; restarting queue HTTP does not reclaim work. Graceful shutdown finishes the batch. Abrupt recovery reuses saved settings/seeds/expansions and adopts matching committed artifacts. GPU-lock contention leaves pending work waiting without unloading idle weights. Preserve references/adapters until consumption and back up project `state/` with media/references/indexes. Keep weights/media/private adapters/settings/SQLite/symlinks outside Git.

`make test` uses fakes; `make smoke` requires a running model and creates a real512px image. Do not start models merely to inspect docs/catalogs or change user queues for tests. ## Resource observability

The running generator serves `/observability` and read-only `/v1/observability`, `/v1/observability/metrics`, `/v1/observability/jobs`, `/v1/observability/jobs/{id}`. The queue API has no metrics or job-log routes. A job view also shows available generation logs; `GET /v1/observability/jobs/{id}/logs?model=<id>&max_bytes=65536` reads bounded tails independently of resource sampling. Limits are 1024–262144 raw bytes in total, across at most ten runtime attempts and five native output files. Runtime logs are `state/job-logs/<id>/attempt-<n>.log`; native logs are the latest per-output files, not attempt-separated. Unknown jobs/model mismatch return404; old jobs can return200 with available:false. Unreadable queue state returns503 job_logs_unavailable. Logs are private, may contain runtime-emitted prompts/paths, and are not pruned by metric retention. Never substitute global shared logs for job attribution. Overview windows are 5m/30m/1h/6h/24h/3d/7d; optional model filtering spans persisted sessions. Job windows are full/1m/5m/15m and include recorded attempts. Use limit/offset for measured-attempt pagination; queue Metrics links open the matching job.

History is local `state/observability/metrics.sqlite3`, separate from queues and external assets. Sampling is 1s during execution / 5s idle plus boundaries; eight days of raw samples are kept and finished attempt summaries persist. Stopped/unmeasured periods remain gaps; do not invent old measurements. CPU is process-tree utilization normalized across all logical CPUs; RAM is summed RSS (shared pages can count twice). GPU is whole-device and includes other apps; its driver memory overlaps unified RAM. Missing counters are null and sampled peaks can miss spikes. Model/session/stage/job/attempt are recorded; do not infer exclusive GPU attribution or exact model-only allocation. Source/store errors are reported independently and must not stop generation. Read the live schema and docs/api.md#observability for fields, limits and examples. No administrator access or extra daemon is needed; serving never installs psutil—use make setup-env after pulling a dependency update.

GET `/v1/observability/lifecycle?window=30d&limit=20&offset=0` reads persistent model load/unload events. Range:24h/7d/30d/90d/all; optional model, action:load/unload, scope:process/weights, job_id and finite current/past end. Successful duration mean/peak and status counts in summary[] cover all matches; data[] is newest-first, with total/limit/offset/has_more. Every event records session/model/action/scope/reason, optional triggering job/attempt, started/finished, status and monotonic duration_seconds. Failed durations stay visible but are excluded from success averages; running/interrupted unknown duration is null. Runtime start is child startup/import-ready; stop includes confirmed owned-group cleanup. Separate weights timing covers resident Z-Image constructor/adapter replacement/release; native CLI weight boundaries and first-inference compilation are not separately timed. Scopes can overlap; never sum them or infer GPU memory release. Warm reuse adds no load. For both sides of a switch use job_id without model, since previous-model unload is attributed to the incoming job. UI event range is independent of graphs; job events span the full job. Events survive sample pruning and restarts, with no old-data backfill; schema2 preserves earlier resource history. Read-only history never reconciles running events or loads a model. Nonfatal lifecycle_error is separate from resource sampling; reads use observability_unavailable 503. No queue-service endpoint. Restart a running generator to enable new instrumentation; preserve user jobs/processes.

## Shared queue and backend switching

`make serve MODEL=<id>` sets the shared default, not an exclusive worker model. Both APIs resolve omission consistently and persist the resolved model on each new job. The generator uses one managed model subprocess and one global worker lease, keeping the API/UI responsive through loading. Switching stops/reaps the previous process before loading another; same-model Z-Image jobs reuse warm weights. Native Chroma/Klein/Qwen children still load per image. LLM refinement/expansion is scoped to the job's model and persisted before rendering. A missing model after admission stays queued with `blocked_reason` while eligible jobs continue. Render failures fail that job without stopping the consumer. Queue positions, pause, Run Now and reordering span every model; no automatic model grouping overrides saved order.

Health version4 identifies `service:imagegen-generator`, `runtime_model_switching:true`, `queue_scope:shared`, `default_model`, nullable `active_model` and `model_loaded` (backend initialized; native per-image weights may already have been released). Discovery lists only setup models and the selected default; unknown/unready new requests are rejected. The queue health identifies `imagegen-queue` and shared scope. The queue contract intentionally has no old-database migration or startup-bound API compatibility. Existing media/catalogs remain usable. A running old queue must be stopped with `make stop-queue` before starting the new version. Do not start real inference or leave maintenance servers running unless requested.

The Edit webpage uses one preview: empty before choosing a source, centered source after upload using the same display bounds as generated results, then the completed edit replaces the source. Generate and Edit keep independent prompts, model/settings, references, masks, expansion previews, batch selections and results while the page is open. Switching tabs restores only that workflow; background completions update their own tab, and the queue stays shared. Photos transfer only through explicit result/gallery reuse. Reloading clears form drafts, but accepted jobs remain durable. With Qwen, dragging a region automatically chooses Selected area; clicking alone does not. Runtime release failures stop the consumer rather than overlap models; inspect the job log and state/model-process/server.log for the parent cleanup traceback, update/restart manually, and retry the failed job if desired. Older versions logged only child output there and may have no useful cleanup trace.
