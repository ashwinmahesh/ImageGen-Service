# Local image model service

Locate the checkout containing `Makefile`, `model_profiles.py`, `server.py` and this README. On the original Mac it is `~/Documents/models/ImageGen-Service`; elsewhere use the supplied folder. Read `README.md` before provisioning or changing settings. This skill is usable directly by any AI tool without installation.

Run `make setup` in a terminal to choose a model from the menu; Enter selects **Z-Image Turbo**. It then asks once for a model store directory; Enter uses the project folder, another absolute path creates per-model symlinks. For scripts use `make setup MODEL=<id> DATA_DIR=/absolute/store NONINTERACTIVE=1`, or omit DATA_DIR to reuse saved/default storage. Valid IDs: `z-image-turbo`, `chroma1-hd`, `chroma1-flash`. The store contains these three model subfolders. Do not pass one model's weights folder as the store. Keep source/environment internal and weights/data on the user's chosen external volume. Reuse existing assets; fail on missing mounts rather than downloading a fallback. Flash setup fetches shared T5/VAE assets without downloading the HD diffusion checkpoint. Realism for Z-Image is the only optional public adapter; never publish personal catalogs/media.

Run `make test` for fake-backend checks. Start `make serve MODEL=<id>` in a retained foreground terminal, optionally `NO_LORAS=1` or `PORT=...`. Plain `make serve` offers the same menu and Enter default. Noninteractive omitted selection defaults to Z-Image. Poll `/health` until ready; confirm `model`, `busy`, `loras_enabled`, paths and `capabilities`. `/v1/models` lists supported/downloaded models. Only one selected backend serves requests. A different request model returns 422; select it at startup instead. Do not replace a busy/unrelated service. Graceful Ctrl-C stops the foreground process.

Use live `/openapi.json` or `/docs` for authoritative fields/defaults. POST `/v1/images/generations` with a prompt and `response_format:"url"`; omit model/steps to use active defaults. Defaults: Z-Image 9 steps (max12), HD40 (max80), Flash8 (max40). `size` dimensions are multiples64, 256–2048. Seed is optional uint32, n is1, prompt max4000characters; Z-Image truncates at512tokens including formatting. Optional `output_dir` is server-local absolute/`~/` path. Every response returns PNG and metadata paths. Optional tags are saved and editable later.

For variations, pass an absolute `reference_image`, or POST raw image bytes to `/v1/reference-images` (20MiB/40MP max) and use its returned path. Output preserves oriented reference aspect ratio; size sets the long edge. `image_strength` is [0,1), higher preserves more; default.6, requires reference and at least2steps. References remain unchanged. This is image-to-image variation, not reliable localized/instruction editing. LoRAs come only from the active model's `/v1/loras`; use ID/strength fields, not prompt tags. A configured trigger phrase is inserted automatically. Strength0–2, one adapter. Base-only mode rejects adapter requests.

The webpage `/` offers generation/reference controls. `/gallery` and GET `/v1/images` combine all model roots, searchable by prompt/tags/model and paginated using limit1–100(default24),offset,sort. Exact repeated tag filters combine with q. Read `/v1/images/{id}` for settings; PATCH `/v1/images/{id}/tags` with `{"tags":[...]}` replaces tags, `[]` clears them. Changes persist in the owning model index without changing original PNG/metadata. Reuse actions prefill for review; cross-model adapters/steps are not transferred. Custom output URLs survive restart through the index; preserve indexes and data paths.

Prefer POST `/v1/jobs` to persist a request and receive202 plus an ID, then poll GET `/v1/jobs/{id}`. Each model's SQLite queue is at `<store>/<model-id>/queue/jobs.sqlite3`, automatically resumed at startup. API jobs default `generate_immediately:false` (ordinary FIFO); the UI defaults true (next free slot ahead of ordinary work, FIFO among immediate jobs, no preemption). The synchronous `/v1/images/generations` remains compatible, defaults immediate=true, and waits on the same durable worker. Use a long timeout for that route. Disconnection never cancels a job. Reuse the same `Idempotency-Key` and request after uncertain submission; different settings with that key return409. Seeds and effective defaults are fixed on admission.

GET `/v1/jobs` accepts status (including pending), limit1–100/offset, and returns totals/navigation. DELETE `/v1/jobs/{id}` cancels only waiting entries (running returns409); DELETE `/v1/jobs` clears waiting work only. History and generated files remain intact. POST `/v1/jobs/{id}/retry` creates a new normal FIFO job from a failed/cancelled record. PATCH `/v1/queue` with `{"paused":true}` persists an ordinary-queue pause, allowing the current image to finish and explicitly immediate work to run. Base-only mode leaves an incompatible adapter job waiting rather than silently changing it.

Graceful shutdown finishes current inference and persists the remainder; an abrupt interruption retries the same job ID/seed from scratch. Committed matching artifacts are reconciled without duplicate generation. Preserve queued references/adapters and back up the database/index/media together. Missing SSDs fail without fallback. GPU_LOCK_FILE or ignored storage.json gpu_lock_file selects a cooperative accelerator lock; this Mac uses the voice services' existing SSD lock. Pending jobs wait for it; it does not unload idle resident models. Inspect `/health.queue` for counts, pause/stage/error. Do not clear user queues or interrupt active work for validation. For actual GPU verification, `make smoke` generates/decodes a512px image using the active defaults. Distinguish this from unit tests. Chroma loads/reclaims GPU weights per request and can be slow. Do not start additional GPU models merely to read catalog or docs. Report the selected model, mode, URL, paths and actual checks; retain media, weights, local settings, catalogs and storage symlinks outside Git.
